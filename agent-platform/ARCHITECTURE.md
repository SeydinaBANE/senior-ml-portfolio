# Agent Platform — Architecture

## Overview

Multi-tenant FastAPI platform with LLM-based intent routing, RBAC (3 roles), usage billing, and Streamlit UI. PostgreSQL for persistence, Redis listed but unused in code.

## Intent routing flow

```
POST /api/v1/run { message }
  → classify_intent(message, tenant_id)
     → query DB for tenant's agents + public agents
     → build agent list: "- name (category): description"
     → ChatOpenAI.with_structured_output(RoutingDecision)
     → returns {agent_name, confidence, reasoning}
  → if agent_name == "__none__" or confidence < 0.5: 422
  → lookup AgentDefinition by name
  → create fresh ChatOpenAI(model=agent.model) with agent.system_prompt
  → ainvoke(message)
  → record_usage(input_tokens, output_tokens, latency_ms)
  → return RunResponse
```

## RBAC enforcement

`require_permission(permission)` returns a closure that takes `Role` and raises `HTTPException(403)` on denial. Used inline in route handlers (not middleware).

## Billing

Configurable per-1k-token prices via env. `record_usage()` inserts a `UsageEvent` row after each successful LLM call. `get_billing_summary()` aggregates SUM/COUNT/AVG per tenant + date range.

## DB models

```
users: id, email (unique), hashed_password, role, tenant_id, is_active
agent_definitions: id, name, description, category, system_prompt, tools (JSON),
                    model, is_public, owner_id (FK→users), tenant_id, tags (JSON)
usage_events: id, tenant_id, user_id (FK), agent_id (FK), input_tokens,
              output_tokens, cost_usd, latency_ms, occurred_at
```

No Tenant table — `tenant_id` is a plain UUID column with no FK constraint.
